# 开发与验收指南

本文承接根 [AGENTS.md](../../AGENTS.md) 的操作规范。执行相应任务前阅读相关章节；不新增审批阶段、固定模板或每次必跑的全仓审查。模块交付状态见 [README](../../README.md)，稳定取舍见 [decisions](../decisions/)，CI 实际入口见 [CI 说明](ci.md)与 [workflow](../../.github/workflows/ci.yml)。

## 开工与隔离

先读目标 Issue、相关决策、实际 Git 状态和消费者，确认目标/非目标、实现负责人、仓库与基线完整 SHA、工作区/分支、允许写入、依赖产物的就绪判据以及验证/交付位置。复用 Issue/PR/交接正文即可；可查信息先查，缺方向或权限才问用户。

- 一位负责人连续完成实现、必要编译和最小真实冒烟；并行工作须输入就绪、写入隔离，不共享索引、build、依赖目录、测试数据或未声明的进程。
- 首先确认所需私有依赖前缀、实际链接版本及真实后端可达性；找到现成能力后直接复用。缺支撑应给出具体缺口，不交空测试骨架冒充已实现。
- 新 worktree/云端 clone 没有未提交规范；核对实际拿到的版本。未发布规则由授权交接者提供明确候选快照/差异与适用范围，不把旧暂存版当最新版。
- 只读不要求全仓洁净；写入时保留他人改动，不把临时产物放进源码或提交。长期结论进入本仓文档/PR，原始 `.state`/会话不作唯一公共依据，也不要求接续者读取 Alice 历史或私有记忆。
- 优先自有进程、动态端口；共享服务须声明复用/互斥、测试数据归属和清理边界。不终止他人进程，不安装或覆盖共享前缀；既有构建无法隔离时先记录阻塞，不擅改入口。

## 接口与职责

新入口先展示最小真实消费方式，确认返回值、失败行为、并发限制和关闭责任，再定义契约测试与一个真实后端。首个任务明确模块/协议范围与公共契约负责人；不默认 HTTP/RPC/MCP 互为前置或同时实现。共享机制由真实重复及契约测试驱动，不预建任意协议插件平台。

| 层或模块 | 责任与边界 |
|---|---|
| HTTP | 协议消息、客户端/服务端、流式契约与后端适配；协程停止等待不等于底层 I/O 完成 |
| RPC | 传输、协议、编解码和客户端/服务端；framework 承载 CallContext、deadline 合并、重试预算、错误分类、未知结果、发现订阅及负载均衡；Stub 接入归 framework/扩展，业务接口与生成 Stub 归 fork 应用 |
| MCP | 协议、transport、client/server；业务工具归应用仓，不下沉 Workbench 领域模型 |
| 配置 | 版本化快照、源适配、watch、重连、去重与关闭；不绑定配置中心，不替代 framework schema 校验、生效策略或业务热更新编排 |
| adapter / coroutine | adapter 持有第三方操作、取消/关闭、错误映射、执行域和请求/连接/缓冲寿命；coroutine 提供运行时等待、唤醒及自身对象安全 |

不把所有文件堆进一个 `src/`；目录与目标共同表达公开契约、模块实现、第三方隔离、依赖支持、分层测试、消费示例和决策。公开头一般在 `include/`；已确认的新 net/Redis 模块例外把公开头与实现并置于 `bbt/infra/net/`、`bbt/infra/redis/`，由公开 target 导出仓根 include 路径。其余实现按 `src/<module>/` 或需要的 adapter 边界组织，构建支持在 `cmake/`，测试/示例/决策分别在 `tests/`、`examples/`、`docs/decisions/`。只有实现需要才建目录；公开/内部头及模块边界必须从构建目标核验，不能只靠命名。

关闭语义按各模块契约判断，不统一改写为同步或异步。新 Redis 的逻辑封口、owner 回收和宿主最终排空见 [Redis net 文档](redis-net.md#关闭与宿主收尾)；旧同步资源不能直接接入新的非阻塞 Close。失败建连的返回也不自动证明资源已释放。

## 依赖接入与上游依据

优先标准库、Boost 1.90、仓内已有能力，再评估必要的新依赖；成熟能力已能满足时不另造。第三方适配使用 C++17 的现代所有权及错误处理，语言标准、新包管理或系统依赖变更须先确认。选择非 Boost 后端须有正确性、协议完整性或架构匹配的可复核依据与用户确认，不预先锁定未验证的库或版本。

新依赖在 Issue/决策中记录维护活跃度（近期发布/提交、Issue/安全响应）、异步/取消/线程模型、平台与编译器、许可证、安全记录、包体/构建成本，以及替换和退出路径。Stars 或单次 benchmark 不能单独决定；依赖自身通过不代表本仓 adapter 或承诺平台通过。版本锁定、许可证/安全核查和最小真实集成均须落实。

使用上游时核对源码 SHA、实际模块、链接路径及对应验证；tag 解析到 SHA，不能把 `/usr/local` 已安装当作版本已固定。协程依据从实际消费 SHA 对应的 [bbtools-coroutine](https://github.com/yqm-307/bbtools-coroutine) `agent-docs/2026-09-07-core-runtime-contract.md`、`api-reference.md`、`user-guide.md` 查起，不把本地 `.sdd` 或旧 README 当唯一真源。`BBT_CORE_SOURCE_DIR` 只是 coroutine 拆分完成前的过渡兼容开关；core 基础模块迁入本仓后同样遵守 infra → coroutine 方向，不新增 core 依赖。

公共 API 默认使用自有或标准库类型，不传播第三方对象、异常、线程模型；无法隔离须明确说明并评审兼容影响。模块依赖显式、公开、可测试且无环，同仓不意味着能引用兄弟内部目录或必须一起构建/部署；回调与控制反转不改变依赖方向。

## 测试要证明什么

用例须以实际断言证明公共行为，不凭测试名、PASS 打印、通过数量或进程退出判断完成。mock/fixture 仅作补充，真实后端的连接、失败、取消、关闭及资源寿命不能由它替代。受控 TCP 或既有私有测试接缝可补充分帧与精确时序，不扩大生产 API 只为测试。

并发与生命周期用例按这条因果链构造：

1. **确认进入目标阶段**：例如拨号已提交、完整命令已到达对端、回收已被屏障扣留。仅线程启动或固定 sleep 不证明进入阶段。
2. **触发被测事件**：Close、取消、超时、断连或释放公开句柄；区分拒连和超时，不以一种失败代替另一种。
3. **检查结果及责任收口**：按契约核对错误码、结果是否只落定一次、后续接纳/流同步状态以及资源归还；资源释放断言须在相关局部对象释放后执行。逻辑 Closed、连接计数为零或 Run 返回中的任一单项不能替代模块要求的完整排空凭据。

若进程寿命运行时存在一次性延迟初始化，资源基线应在受控初始化后建立，并说明基线包含什么；不得通过排除 fd 类型、关闭断言或依赖进程退出掩盖泄漏。运行时边界复用仓内既有测试入口，不为测试捏造 Stop/restart。

失败保留最小复现与实际时序，定位后修复并复验；不能通过 skip、返回成功、放宽断言或重复重跑挑选绿色结果核销。历史偶发失败须有证据才能归因，之后未复现不等于根治。已有失败被确定为与本改动无关时，记录对照和限制。

真实服务测试只操作有归属的测试数据，成功/失败路径都清理，并按需要读回确认；不得清库或修改共享服务配置。缺环境/权限如实 BLOCKED，不能以未实现代替环境阻塞说明。

## 本地验证

本地必走冒烟 + 本次开发功能的单测 + 直接耦合功能的单测；本地不跑全量，全量走 PR CI。新 configure 加 `-DCMAKE_CXX_COMPILER_LAUNCHER=ccache`。增量限定 `--target`；禁止 bare `--parallel`、bare `ninja` 或 `make -j$(nproc)`。

本地编译固定最多 2 个并行任务，增量与全量均适用，显式写 `--parallel 2` 或 `-j2`，不按逻辑核数放大。宿主是 12 核 / 15 GiB 的共享 WSL，编译峰值吃内存而非 CPU：按核数推导的并发会让单次构建耗尽内存，并把同机并行工作的其他 agent 一起卡死。并发是内存预算，不是吞吐调优。

下面是命令模板，必须替换目录和实际目标；模板不是对任意模块的已运行证明。Redis 的具体配置与消费命令见[模块文档](redis-net.md#构建和消费)，其他模块查各自入口。

```bash
cmake --build <private-build> --target <affected-targets> --parallel 2
ctest --test-dir <private-build> -j1 -R '<affected-tests>' --output-on-failure --no-tests=error
```

同机多个 agent 时，构建、测试、profile 与 perf 复用宿主既有队列 `/tmp/bbt-build.lock`（`flock` 持锁执行），不各建锁或队列；找不到入口先查清，不直接并行启动重任务。确需本地全量同样走该锁，一次一个构建，并仍限 `--parallel 2`；这是例外，不把每次交付变成本地全量。队列只保证互斥，不提供内存硬隔离。

重任务启动前检查可用内存与既有任务；一次只运行一个重任务，内存不足则等待或报告阻塞，不靠反复重试、增加 swap 或清空缓存推进。纯文档修改做 `git diff --check`、链接/事实核对和适用审查，无需为文档重跑产品测试。上述代码块为参数模板，未作为一条完整命令执行。

新增目标或测试须核对 **构建选项 → 实际构建目标 → CTest 注册集合 → 实跑结果 → CI 执行路径**。注册、执行和预期范围须一致，跳过或缺项按验收条件处理并明确列出。没有进入 workflow 的路径，即使已有 CI 全绿也仍是未覆盖；CI 接线变更另行确认，不在文档中宣称已完成。

实际 runner、依赖准备、Redis/Mongo 临时容器及清理方式以现役 workflow/脚本和精确 run 为准，不根据旧镜像印象假定后端存在。通用 CI 方法见 [CI 说明](ci.md)；Redis/Mongo 真实后端 live 编排的边界记录在对应 PR/Issue 验收评论（运行证据不入仓），新 Redis 入口的覆盖边界见[验证边界](redis-net.md#验证边界)。监视客户端 EOF 或退出码不自动等于 job 失败，须回读 run/job 实际结论。

## 审查与交付

关键契约、依赖及生命周期变更须由未参与实现者独立审查；不将实现者自测或自述当作审查通过。交付包含实际 build/test/consume 命令、仓库与依赖版本、选集/注册与执行结果、资源清理凭据及未覆盖项；验证强度与改动风险匹配，不重复已落盘且版本未变的证据。

对外变更读回精确对象与 SHA。PR 检查使用 `gh pr checks` 核对当前 head，合并另核 state/mergedAt/merge SHA；本地通过、PR 通过、已合并和消费者切换分别报告。没有新授权不得自行合并/发布或修改 CI、基础设施；不以规则说明替代平台保护。

文档使用中文，代码标识符、命令及错误保留原文。README 维护交付状态，模块文档维护当前契约和复现入口，decisions 保存稳定取舍，Issue/PR/Review 留逐次进展与验收。原始日志、构建产物、会话、凭据和私有路径不入仓；不把同一份状态在多处重复维护。未完成支持不得写成已交付事实。

## 旧仓迁移与支撑缺口

`bbtools-http`、`bbtools-rpc`、`bbtools-network`、`bbtools-conet` 只提供历史实现与测试素材，不是新 API 权威。迁移先盘点行为、调用者、许可证、测试与可保留算法，再确定本仓契约；禁止整仓复制后宣称现代化。由迁移任务指定历史消费者/许可盘点的产出者与接收者，不阻塞无迁移需求的协议研究。

新增功能进入本仓；旧仓默认只做迁移所需阻塞修复、文档和安全维护。归档、只读、删除、重命名或消费者切换须单独确认。迁移完成须有消费者切换、兼容/迁移说明、真实集成和回退证据；旧代码仍存在不构成长期双写理由。经 framework 消费时不得绕过其生命周期、配置或安全约束。

向 core/coroutine 报支撑缺口前先与拥有者去重，并附双方完整 SHA、最小复现/测试标识、期望契约位置、真实命令以及失败/资源寿命时序。无实证缺口不要求底层重写，不以改变 Stop 掩盖 adapter 资源错误；发布交接给模块公开目标、契约引用与验证，消费者仍须核对实际链接版本和自身集成。
